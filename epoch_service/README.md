# Определитель эпохи (Text Epoch)

Веб-сервис, который определяет по русскому тексту **жанр** (поэзия, проза, публицистика), а затем **период
написания** (шаг 25 лет, 1800–1949) и подсвечивает в тексте слова-маркеры эпохи. Порядок всегда такой:
**сначала жанр, потом период внутри жанра**; маркеры берутся из словаря именно этого жанра.

- Жанр можно выбрать вручную (необязательно) или оставить на автоматическое определение.
- Период оценивает обученная модель (rubert, дообученный на жанр и период).
- Слова-маркеры подсвечены прямо в тексте; при наведении видно, на какую эпоху указывает слово и во сколько раз
  чаще оно встречается в ней, чем в других эпохах этого жанра.
- Без модели сервис тоже запускается: период тогда оценивается по словарям (заглушка), жанр нужно выбрать или
  он определяется по признакам текста.

## Быстрый старт

Нужен Python 3.10 или новее. Для заглушки внешних библиотек не нужно.

```bash
python -m service --port 8000      # открыть http://127.0.0.1:8000/
```

С обученной моделью (см. раздел ниже) сначала `pip install -r requirements-nn.txt`, затем тот же запуск.
В консоли будет видно, что загрузилось: `модели: rubert (model_run)` или `модели: stub-0.1 (заглушка)`.
То же самое показывает `GET /api/health`.

## Модель

Файлы весов (≈1,4 ГБ) слишком велики для GitHub, поэтому **в репозитории их нет**.

1. Скачайте папку с моделью с Google Диска:
   [model_run](https://drive.google.com/drive/folders/1LLHrYofftgc2RpjRvbIEPY6sAuZKhza9?usp=sharing).
2. Положите её в корень проекта под именем `model_run`. Нужны только эти файлы (`preds_*.jsonl` не нужны):
   ```
   model_run/meta.json                  (необязательно)
   model_run/model/model_info.json
   model_run/model/genre/   era/   tok/
   ```
   Другой путь: переменная окружения `EPOCH_NN_DIR`.
3. `pip install -r requirements-nn.txt` (torch и transformers).
4. Запустите сервис. Если папка `model_run` на месте, модель подхватится сама. Если чего-то не хватает, сервис
   не запустится и напишет, чего именно. `EPOCH_MODELS_FACTORY=stub` принудительно включает заглушку.

Поддерживаются запуски rubert и xlmr без словаря. Запуски tfidf и `*_dict` (файлы `model.joblib`,
`booster.joblib`) отклоняются. На CPU ответ занимает несколько секунд, на длинных текстах дольше.

**Как работает модель.** Две сети: жанр по тексту и период по паре «жанр, текст», поэтому выбранный вручную жанр
влияет на оценку периода. Текст режется на фрагменты по словам (длина из `meta.json`, поле `frag_words_median`,
иначе 220), вероятности фрагментов усредняются по логарифмам, не более 16 фрагментов. Перед моделью текст
приводится к виду, на котором она училась (шаг 2 пайплайна: ѣ, і, ѳ, ѵ и конечный ъ заменяются на современные).

**Качество** (по отчёту об экспериментах, test, по фрагментам): QWK периода 0,818, точность периода 0,546,
±1 период 0,893, ошибка около 15 лет, точность жанра 0,923. Эти цифры получены на тестовой выборке корпуса; на
произвольных текстах (особенно коротких или из другой эпохи) качество может быть ниже.

## Как определяется жанр

По умолчанию жанр определяет **эвристика по признакам текста** (длина строк, диалоги, глаголы прошедшего времени,
отвлечённая лексика, `epoch/stubs.py`). Жанровая сеть модели при проверках на произвольных текстах ошибалась
заметно чаще, поэтому она не используется и даже не загружается (это экономит около 700 МБ памяти).
Эвристика на корпусе отдельно не оценивалась. Если она ошиблась, выберите жанр вручную: карточки справа от
текста. Вернуть жанровую сеть: `EPOCH_GENRE=model`.

## Словари маркеров

Словарь на каждый жанр: `dictionaries/dict_<жанр>_form.json`, их создаёт шаг 4 пайплайна
(`04_marker_candidates.py --unit form`). Формат:

```json
{"genre": "проза", "unit": "form", "eras": ["1800-1849", "..."],
 "markers": {"помещик": {"era": "1850-1899", "log_ratio": 3.1}}}
```

- Минимум нужны поля `genre`, `eras`, а у каждого слова `era` и `log_ratio`. Словари `unit=lemma` не поддерживаются.
- Вес маркера: `log_ratio` относительно 95-го процентиля словаря жанра, обрезанный до 0..1.
- **Периоды словаря и модели могут отличаться** (например, словарь по 50 лет, модель по 25): слово подсвечивается,
  если его эпоха пересекается с найденным периодом. Страница об этом предупреждает.
- Сейчас в папке лежат **демонстрационные** словари (слова подобраны вручную, в файлах `"demo": true`): замените их
  своими файлами из шага 4. Папка словарей: `EPOCH_DICT_DIR`.

## Структура

| Файл | Назначение |
|---|---|
| `service/wsgi.py`, `service/__main__.py` | HTTP-слой (чистый WSGI, без зависимостей): страница, статика, API |
| `service/static/` | интерфейс: выбор жанра, текст с подсветкой, результат |
| `epoch/analyzer.py` | конвейер: жанр, словарь жанра, период, маркеры |
| `epoch/neural.py` | подключение обученной модели из `model_run` |
| `epoch/stubs.py` | заглушки: жанр по признакам текста, период по словарю |
| `epoch/dictionary.py` | чтение и проверка словарей |
| `epoch/normalize.py` | нормализация и токенизация, совпадающие с шагами 2 и 4 пайплайна |
| `epoch/models.py` | интерфейсы `GenreModel`, `EpochModel`, выбор модели |
| `epoch/api.py` | валидация запросов и коды ошибок |
| `dictionaries/` | словари маркеров |
| `model_run/` | модель (скачивается отдельно, в git не хранится) |
| `scripts/make_demo_dictionaries.py` | создание демонстрационных словарей |
| `tests/` | тесты |

Позиции слов в ответе (`start`, `end`) относятся к тексту, как его прислал пользователь, в том числе с
дореформенной орфографией: нормализация не меняет длину текста.

## API

`GET /api/health`: состояние сервиса, заглушка ли, способ определения жанра, загруженные словари и предупреждения;
503, если ни одного словаря нет.

`POST /api/analyze` (также `/analyze`), тело: `{"text": "...", "genre": "проза"}`. Поле `genre` необязательное:
если задано (`поэзия`, `проза`, `публицистика`), определение жанра пропускается; `auto` или отсутствие поля
означает автоматическое определение. Текст: от 50 до 10 000 символов.

Ответ 200:

| Поле | Значение |
|---|---|
| `genre`, `genre_score` | жанр и его вероятность |
| `genre_source` | `model` или `user` |
| `genre_method` | `user` (выбран вручную), `heuristic` (по признакам текста) или `model` (жанровая сеть) |
| `genre_scores` | вероятности всех жанров |
| `period`, `period_range`, `granularity`, `score` | период, его границы, длина в годах, вероятность |
| `alternatives` | до двух следующих периодов |
| `period_scores` | вероятности всех периодов по порядку |
| `dated_markers` | слова-маркеры, указывающие на найденный период: `text, start, end, category, weight, log_ratio, points_to, source`; по возрастанию `start`, не более 300 |
| `markers_found` | сколько слов словаря найдено всего, включая указывающие на другие эпохи |
| `warnings` | `short_text` (короче 400 знаков), `no_dictionary` |
| `dictionary`, `stub`, `text_length`, `model_version` | сведения о словаре и модели |

Ошибки: `{"error": код, "message": текст}`. Коды: `empty_text`, `text_too_short` (< 50), `text_too_long` (> 10 000),
`invalid_request`, `unknown_genre`, `unsupported_language` (422), `model_unavailable` (503), `internal_error` (500).

## Другие модели

Правок в сервисе не нужно. Напишите модуль с функцией `build(dictionaries)`, которая возвращает
`(genre_model, epoch_model, "версия")`, и запустите с `EPOCH_MODELS_FACTORY=ваш_модуль:build`.
`genre_model.predict(text)` возвращает `{жанр: вероятность}`; `epoch_model.predict(ctx)` получает
`ctx.text, ctx.genre, ctx.eras, ctx.hits, ctx.n_tokens` и возвращает `{период: вероятность}`;
у `epoch_model` должен быть атрибут `eras` (список периодов).

## Тесты

```bash
python -m unittest discover tests -v
```

Проверено: тесты (38, один пропускается без файла `02_extract.py`), запуск сервера, маршруты и коды ошибок,
интерфейс в браузере (подсветка, выбор жанра, мобильная ширина, вставка HTML в текст не исполняется).
**Не проверялось:** загрузка настоящих весов и работа с ними (в среде проверки не было весов, torch и GPU),
а также запуск через `gunicorn`.

## Ограничения

- Маркер показывает слово, которое в обучающем корпусе чаще встречается в эпохе, а не причину датировки.
- Тексты короче 1000 знаков оцениваются менее надёжно: сервис предупреждает, но не отказывает.
- Остатки дореформенной орфографии (`-аго`, `-ыя`, `ея`) в словари по умолчанию не попадают (шаг 4, `--orth drop`),
  поэтому текст в старой орфографии подсвечивается только лексикой.
- Результат: оценка модели, а не окончательная датировка.
