# Веб-сервис Text Epoch

Веб-прототип для определения периода создания русского текста. Текущий сценарий намеренно двухэтапный: **сначала пользователь выбирает жанр, затем сервис ищет датирующие маркеры в словаре этого жанра и оценивает период**.

> Сейчас это работающая заглушка на подготовленных словарях из `../markers/dict_*_form.json`, а не нейросеть. Жанр выбирает пользователь; автоматический классификатор жанра пока не подключён.

## Структура

| Файл | Назначение |
|---|---|
| `main.py` | FastAPI: маршруты, валидация запросов, история |
| `nlp.py` | загрузка жанровых JSON-словарей и расчёт периода по найденным маркерам |
| `static/index.html` | интерфейс: выбор жанра → ввод текста → результат |
| `API.md` | описание текущего API |
| `test_api.py` | интеграционные проверки запущенного сервера |
| `requirements.txt` | Python-зависимости |

## Запуск локально

Нужен Python 3.10 или новее.

```bash
cd fastAPI_WEB
python -m venv .venv
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

macOS / Linux:

```bash
source .venv/bin/activate
```

Установка и запуск:

```bash
pip install -r requirements.txt
uvicorn main:app --reload
```

Откройте <http://127.0.0.1:8000/>. Документация API: <http://127.0.0.1:8000/docs>.

Проверка (в другом окне терминала, при работающем сервере):

```bash
python test_api.py
```

## Как работает текущая заглушка

1. Пользователь вручную выбирает один из трёх жанров: поэзия, проза, публицистика.
2. `nlp.py` загружает соответствующий JSON из `markers/`.
3. Текст приводится к нижнему регистру, `ё` нормализуется в `е`; слова ищутся по точным словарным формам.
4. Для каждого совпадения берётся период `era` и сила маркера `log_ratio`.
5. Сумма свидетельств по периодам нормируется; наиболее поддержанный период показывается как результат.
6. Интерфейс выводит найденные маркеры и их позиции в исходном тексте.

Периоды, присутствующие в словарях: `1800-1849`, `1850-1899`, `1900-1924`, `1925-1944`. Если совпадений нет, сервис честно сообщает, что период не определён.

Это упрощённая демонстрационная эвристика: она не учитывает контекст, не распознаёт все словоформы и не должна трактоваться как научно достоверная датировка. Поле `stub: true` присутствует в ответе API, чтобы клиент мог отличать заглушку от будущей модели.

## API

### `GET /api/genres`

Возвращает допустимые жанры:

```json
{"genres": ["поэзия", "проза", "публицистика"]}
```

### `POST /api/analyze`

Запрос:

```json
{
  "genre": "проза",
  "text": "Сей человек долго смотрел на дорогу и думал о своей судьбе..."
}
```

- `genre`: `поэзия`, `проза` или `публицистика`;
- `text`: от 50 до 10 000 символов.

Ответ содержит `result` с жанром, предполагаемым периодом, оценкой, альтернативами и массивом `dated_markers`. `meta` содержит длину текста, выбранный жанр и время обработки.

### Служебные маршруты

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | состояние сервиса и число запросов |
| GET | `/api/history?limit=10` | последние запросы в памяти процесса |
| GET | `/docs` | Swagger UI |
| GET | `/` | веб-интерфейс |

## Как позже подключить нейросеть

Не нужно заранее иметь все файлы модели на этом компьютере. Когда напарница сможет передать артефакты, попросите у неё:

- веса модели и конфигурацию (или ссылку на доступное хранилище);
- токенизатор, если он отдельный;
- точный список классов и порядок периодов/жанров;
- код предобработки текста и инференса;
- версии библиотек и пример входа/выхода на одном тексте;
- сведения о лицензии и допустимом способе распространения весов.

После этого модель подключается на серверной стороне внутри `nlp.py` или отдельного `model.py`. Интерфейс не должен знать, нейросеть или заглушка выполняет анализ: он отправляет жанр и текст в `/api/analyze` и отображает ответ. Если будущая модель сама определяет жанр, API можно будет расширить отдельным режимом, сохранив текущий сценарий как ручной выбор.

**Важно:** пока файлов модели нет, сервис не скачивает и не пытается загружать RuBERT/XLM-R. Веб-приложение полностью работает на имеющихся маркерах.
