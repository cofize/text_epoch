# Реестр рисков

**Срок:** пара 2 · **Обновляется:** на каждой вехе

| № | Риск | Вероятность | Последствия | План действий |
|---|---|---|---|---|
| 1 | собранных данных меньше расчётного | средняя | недостаточная точность анализатора | при нехватке данных укрупнить периоды; объединить редкие жанры; убрать разделение по жанрам|
| 2 | разметка из источника оказалась ненадёжной | высокая | ограничение потолка качества, метрики занижены/завышены | вынужденная ручная разметка/создание инструмента для разметки; выборочная проверка (например, 100 текстов) с подсчётом согласия разметчиков; для текстов с датой-диапазоном брать середину диапазона и фиксировать ширину диапазона |
| 3 | контракт API пришлось менять после написания интерфейса | средняя | переписывание интерфейса веб-команды, риск не успеть к совместной демонстрации | зафиксировать контракт до Вехи 1, закладывать в ответ поля с запасом (жанр, период, уверенность, маркеры); любые изменения только через версионирование контракта и заглушку из API_CONTRACT.md |
| 4 | связь жанра и эпохи в данных. При разной доле жанров в разные эпохи модель может научиться угадывать эпоху по жанру, а не по языку | высокая | ступень «сначала жанр, потом дата» не добавит качества, а гипотеза о жанровой специфике признаков не подтвердится | сбалансировать корпус, взять выборку и оценить как модель справляется внутри жанра и кросс-жанрово - оценить подтверждается ли гипотеза и стоит ли её брать в расчёт |
| 5 | модель не превосходит базовое решение (TF-IDF + линейная модель, ChangeIsKey/text-dating) | средняя | нет содержательного вклада и смысла в проекте| Сначала построить сильный простой baseline; добавлять сложность поэтапно; фиксировать все запуски в журнале экспериментов; отрицательный результат с разбором ошибок - тоже результат |

**Риски, характерные для этих проектов:**

- собранных данных меньше расчётного;
- доля дубликатов и мусора выше ожидаемой;
- источник закрыл доступ;
- разметка из источника оказалась ненадёжной;
- модель не превосходит базовое решение;
- вычислительных ресурсов недостаточно;
- контракт API пришлось менять после написания интерфейса;
- участник команды выбыл;
- модель слишком тяжёлая для публикации.
