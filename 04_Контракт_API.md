## Эндпоинт

**Адрес:** `/analyze` (базовый URL сервиса уточняется при развёртывании)  
**Метод:** POST  
**Формат:** `Content-Type: application/json; charset=utf-8`

## Запрос

```json
POST /analyze
{ "text": "строка" }
```

| Поле | Тип | Обязательно | Описание | Ограничения |
|---|---|---|---|---|
| text | string | да | входной текст пользователя | от 50 до 10 000 символов |

Позиции в ответе (`start`, `end`) считаются **по исходному тексту**, как его прислал клиент, до любой нормализации на стороне сервера.

## Ответ при успехе

```json
{
  "genre": "проза",
  "genre_score": 0.91,
  "period": "1850-1899",
  "period_range": { "from": 1850, "to": 1899 },
  "granularity": 50,
  "score": 0.74,
  "alternatives": [
    { "period": "1900-1949", "score": 0.19 },
    { "period": "1800-1849", "score": 0.05 }
  ],
  "dated_markers": [
    { "text": "Онъ", "start": 0, "end": 3, "category": "орфография",
      "weight": 0.42, "points_to": "1850-1899", "source": "rule" },
    { "text": "вечеромъ", "start": 26, "end": 34, "category": "орфография",
      "weight": 0.38, "points_to": "1850-1899", "source": "rule" },
    { "text": "комнатѣ", "start": 41, "end": 48, "category": "орфография",
      "weight": 0.51, "points_to": "1850-1899", "source": "model" }
  ],
  "model_version": "baseline-0.1"
}
```

*(пример для текста «Онъ вернулся домой поздно вечеромъ, и въ комнатѣ было тихо.»)*

| Поле | Тип | Описание |
|---|---|---|
| genre | string | жанр текста, одно значение из закрытого списка: `поэзия`, `проза`, `критика/публицистика`, `право` |
| genre_score | number | уверенность в жанре, от 0 до 1 |
| period | string | период написания в виде метки `«ГГГГ-ГГГГ»`, например `"1900-1949"` или `"1910-1919"` |
| period_range | object | то же числами: `from`, `to` (оба года включительно) |
| granularity | integer | ширина периода в годах: `50` или `10`; зависит от жанра и доступных данных |
| score | number | уверенность модели в периоде, от 0 до 1 (чем больше, тем увереннее) |
| alternatives | array | до 2 других периодов с оценками; может быть пустым массивом `[]` |
| dated_markers | array | языковые признаки, повлиявшие на решение; может быть пустым массивом `[]` |
| model_version | string | версия модели; у заглушки `"stub-1"` |

Поля `period`, `score`, `genre` и `dated_markers` сохранены из версии 1.0. Остальные добавлены. Интерфейс, написанный по 1.0, продолжит работать, лишние поля он игнорирует.

**Список жанров** закрытый и может расширяться только с повышением версии контракта.

**Периоды** в рамках одного ответа всегда непересекающиеся и подряд идущие. Метки на деле возможны только такие: `1700-1749`, `1750-1799`, `1800-1849`, `1850-1899`, `1900-1949`, `1950-1999`, `2000-2026`, для десятилетий `1910-1919` и т. п. Если данных для жанра недостаточно для десятилетий, возвращается `granularity: 50`.

Элемент `dated_markers`:

| Поле | Тип | Описание |
|---|---|---|
| text | string | слово или форма, оказавшие влияние на решение |
| start | integer | позиция начала во входном тексте (номер символа Unicode, с нуля) |
| end | integer | позиция конца (не включительно), нужна интерфейсу для подсветки |
| category | string | тип маркера: `орфография`, `лексика`, `морфология`, `синтаксис`, `прочее` |
| weight | number | вклад в решение, от 0 до 1; интерфейс может использовать для интенсивности подсветки |
| points_to | string | период, на который указывает этот маркер (метка в формате `period`) |
| source | string | `rule` (лингвистическое правило) или `model` (признак из модели) |

Правила для `dated_markers`:
- элементы упорядочены по возрастанию `start`; пересечений нет;
- `text` совпадает с подстрокой `[start:end]` входного текста;
- число маркеров не больше 30;
- маркер показывает признак, коррелирующий с периодом в обучающем корпусе, а не причину датировки: так, слово «колхоз» указывает на тему, а не на язык эпохи.

## Ответ при ошибке

```json
{ "error": "код", "message": "текст для пользователя" }
```

| Ситуация | Код | HTTP |
|---|---|---|
| Пустой текст | `empty_text` | 400 |
| Текст длиннее допустимого | `text_too_long` | 400 |
| Текст короче допустимого | `text_too_short` | 400 |
| Некорректный запрос (нет поля `text`, не строка, невалидный JSON) | `invalid_request` | 400 |
| Текст не на русском языке | `unsupported_language` | 422 |
| Модель временно недоступна | `model_unavailable` | 503 |
| Внутренняя ошибка сервера | `internal_error` | 500 |

Низкая уверенность модели — это **не ошибка**: возвращается обычный ответ 200 с низким `score`, и интерфейс сам решает, как это показать (рекомендуемый порог для предупреждения: `score < 0.4`).

## Ограничения

**Максимальная длина текста:** 10 000 символов (длинные тексты сервер режет на фрагменты и агрегирует ответы)  
**Минимальная длина текста:** 50 символов  
**Ожидаемое время ответа:** до 5 секунд  
**Нужен ли индикатор загрузки в интерфейсе:** да

**Что модель не умеет** (для пояснения в интерфейсе):
- литература после 1950 года (в обучающих данных почти нет);
- тексты до 1700 года;
- переводы: определяется эпоха языка перевода, а не оригинала;
- разговорные и интернет-тексты.
