# Подготовка датасета

В папке находятся три последовательных скрипта, которые формируют корпус
фрагментов из метаданных и XML-дампа русской Викитеки.

## Схема процесса

```text
meta.jsonl
   │
   ▼
01_select.py ──► selected.csv
                     │
ruwikisource.xml.bz2 │
        │            │
        └──► 02_extract.py ──► fragments.jsonl
                                      │
selected.csv ─────────────────────────┤
                                      ▼
                              03_build_dataset.py
                                      │
                                      ▼
                               dataset.jsonl
```

В репозитории дополнительно лежат уже подготовленные `train.jsonl`, `val.jsonl`
и `test.jsonl`. Исходные `meta.jsonl` и XML-дамп в архив не включены.

## Требования

Для скриптов используются Python, `pandas` и `lxml`:

```bash
pip install pandas lxml
```

Команды запускаются из этой папки. Пути к входным и выходным файлам можно
задавать аргументами командной строки.

## 1. `01_select.py` — отбор страниц

**Вход:** `meta.jsonl`, JSONL-файл с метаданными страниц.

**Выход:** `selected.csv`.

Скрипт построчно читает метаданные и оставляет записи, которые:
- имеют известный год в диапазоне 1800–1944;
- не отмечены как перевод;
- не имеют `year_source == "conflict"`;
- имеют длину не менее 500 символов;
- относятся ровно к одному из выбранных жанров.

Жанр берётся из поля `genre`, если оно есть; иначе определяется по точным
названиям категорий Викитеки. Поддерживаются `поэзия`, `проза`,
`публицистика`.

Дополнительно скрипт:
- формирует `work` из части заголовка до первого `/`;
- формирует `group`: автор, а если автор не указан — произведение;
- вычисляет 25-летнюю корзину `bin`.

Запуск с параметрами по умолчанию:

```bash
python 01_select.py --meta meta.jsonl --out selected.csv
```

Основные параметры:

| Аргумент | По умолчанию | Назначение |
|---|---:|---|
| `--meta` | `meta.jsonl` | входные метаданные |
| `--out` | `selected.csv` | выходной CSV |
| `--year-min` | `1800` | нижняя граница года |
| `--year-max` | `1944` | верхняя граница года |
| `--bin-years` | `25` | ширина временной корзины |
| `--min-length` | `500` | минимальная длина страницы |
| `--genres` | `проза,публицистика,поэзия` | список жанров через запятую |

## 2. `02_extract.py` — извлечение и нарезка фрагментов

**Вход:** XML-дамп Викитеки (`.xml` или `.xml.bz2`) и `selected.csv`.

**Выход:** `fragments.jsonl`.

Скрипт потоково обходит страницы XML, берёт только пространство имён 0
и страницы, прошедшие отбор на первом шаге. Для каждой страницы он:
1. удаляет комментарии, сноски, таблицы, шаблоны, категории, вики-ссылки,
   HTML-теги, заголовки и строки с библиографическими источниками;
2. проверяет наличие старой орфографии и сохраняет булев флаг `old_orth`;
3. нормализует символы `ѣ → е`, `ѳ → ф`, `і → и`, `ѵ → и` и снимает
   конечный твёрдый знак после согласной;
4. режет поэзию по строкам, а прозу и публицистику — по предложениям;
5. собирает фрагменты целевого размера около 40 слов для поэзии и 70 слов
   для остальных жанров;
6. оставляет фрагменты длиной 25–220 слов, с долей кириллических букв
   не менее 90% и долей цифр менее 5%;
7. ограничивает число фрагментов с одной страницы параметром `--per-page`.

Запуск:

```bash
python 02_extract.py \
  --dump ruwikisource.xml.bz2 \
  --selected selected.csv \
  --out fragments.jsonl
```

Параметры:

| Аргумент | По умолчанию | Назначение |
|---|---:|---|
| `--dump` | обязателен | путь к XML или XML.BZ2 дампу |
| `--selected` | `selected.csv` | таблица отобранных страниц |
| `--out` | `fragments.jsonl` | выходной JSONL |
| `--per-page` | `12` | максимум фрагментов с одной страницы |
| `--seed` | `0` | seed случайного отбора фрагментов |

Формат строки `fragments.jsonl`:

```json
{"page_id":123,"frag_id":"123_0","text":"Текст фрагмента...","n_words":67,"old_orth":false}
```

## 3. `03_build_dataset.py` — балансировка и разбиение

**Вход:** `fragments.jsonl` и `selected.csv`.

**Выход:** один JSONL-файл, заданный аргументом `--out`. В каждой записи
есть поле `split` со значением `train`, `val` или `test`.

Скрипт:
- соединяет фрагменты с метаданными по `page_id`;
- перемешивает записи с фиксированным seed;
- ограничивает вклад одного произведения;
- исключает малочисленные ячейки «жанр × 25-летняя корзина»;
- выравнивает оставшиеся ячейки до размера самой маленькой из них
  (или до значения `--per-cell`);
- распределяет записи по split хэшированием `group` (автор или произведение),
  либо `work`, если указан `--split-by work`.

Запуск:

```bash
python 03_build_dataset.py \
  --fragments fragments.jsonl \
  --selected selected.csv \
  --out dataset.jsonl
```

Параметры:

| Аргумент | По умолчанию | Назначение |
|---|---:|---|
| `--fragments` | `fragments.jsonl` | фрагменты |
| `--selected` | `selected.csv` | метаданные отбора |
| `--out` | `dataset.jsonl` | итоговый JSONL |
| `--cap-per-work` | `40` | максимум фрагментов на произведение |
| `--min-cell` | `1000` | минимальный размер ячейки жанр × период |
| `--per-cell` | `0` | размер ячейки; `0` означает минимум среди оставшихся |
| `--split-by` | `group` | ключ разбиения: `group` или `work` |
| `--seed` | `0` | seed перемешивания и разбиения |

**Важно:** реализация скрипта назначает split по хэшу, а не гарантирует
точные пропорции 80/10/10. Результат зависит от групп и seed. Скрипт в архиве
не создаёт отдельные `train.jsonl`, `val.jsonl`, `test.jsonl`: он пишет один
файл с колонкой `split`.

## Готовые выборки в репозитории

В `dataset.jsonl/` уже находятся:
- `train.jsonl` — 5 780 строк;
- `val.jsonl` — 720 строк;
- `test.jsonl` — 718 строк.

В этих трёх файлах поле `split` отсутствует: имя файла обозначает часть
выборки. Эти файлы использовались в переданном отчёте сравнения моделей.

## Важные замечания

- Полный цикл требует `meta.jsonl` и дампа Викитеки; их нет в текущем архиве.
- Скрипт `03_build_dataset.py` и фактические готовые split-файлы не совпадают
  по способу выдачи результата. Для точного воспроизведения эксперимента
  нужен исходный скрипт/ноутбук, которым были сформированы три JSONL-файла.
- Порог `--min-cell=1000` в коде скрипта может удалить все ячейки при текущем
  размере данных; в старой карточке датасета описаны иные параметры. Перед
  повторной сборкой нужно сверить актуальную конфигурацию.
- Дедупликация текстов в этом скрипте не выполняется.
